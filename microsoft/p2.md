### Comparative Architecture Table: Clustered Routing Paradigms

| Feature / Metric | Stateless Redis Pub/Sub (NexusIDE) | Sticky Sessions (HAProxy / Cookie) | P2P gRPC Mesh |
| :--- | :--- | :--- | :--- |
| **Pod Coupling** | **Completely Stateless** (any pod takes any user) | High Coupling (all room users pinned to 1 pod) | Complex peer discovery & mesh |
| **Failover Impact** | **Sub-second** (client reconnects to any pod) | High (pod crash severs all room users) | Moderate (reroute peer streams) |
| **Load Distribution** | **Uniform** across all cluster pods | Skewed (hot workspace overloads 1 pod) | Uniform across mesh |
| **Cross-Pod Latency** | **Sub-5ms** over local Redis network | N/A (no cross-pod communication) | Sub-3ms direct TCP |
| **Network Overhead** | Low (binary buffers via `pmessageBuffer`) | Minimal | High (mesh $N \times N$ TCP sockets) |

## 3. Visual Failure Modes & Recovery Mechanics

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                         5 CRUCIAL FAILURE MODES: SYSTEM BEHAVIOR MATRIX                          │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

| Failure Mode | Root Trigger | Immediate System Impact | Recovery / Mitigation Mechanism | Automated Verification |
| :--- | :--- | :--- | :--- | :--- |
| **1. Redis Crash / Network Sever** | Redis 7 process crashes or OOMs. | Pub/Sub drops; Redlock `SET NX` fails. | Pods fall back to **in-memory mutex** (`inMemoryLocks.has`); local users continue editing safely without crashes. | `test.sh --chaos` (mid-tx disconnect) |
| **2. Lock Lease Expiry Under Load** | Database write takes 5200ms (>5000ms TTL). | TTL expires; Pod 2 acquires lock before Pod 1 finishes. | Pod 1's atomic Lua script checks `redis.get == POD_ID`; aborts deletion of Pod 2's lock (`return 0`). | `test.sh --integration` (TTL timeout) |
| **3. Recursive Pub/Sub Storm** | Developer forgets origin tag in new handler. | Pods echo messages back and forth in an infinite loop. | Enforce `'redis'` origin guard: `if (origin !== 'redis') publish()`. Checked by property fuzzer. | `test.sh --property` (zero-rebroadcast test) |
| **4. Cluster Snapshot Invalidation** | User restores snapshot on Pod 1. | Pod 2 holds stale in-memory `WSSharedDoc` in RAM. | Pod 1 publishes `workspace:evict:<id>`. All pods evict in-memory docs and send close code `4100`, forcing clean refresh. | `test.sh --snapshot` (cluster evict) |
| **5. DB Connection Pool Exhaustion** | 20 workspaces flush debouncers simultaneously. | PostgreSQL runs out of pool connections (pool limit: 25). | Sized with 2s fail-fast timeout; staged in Redis write-behind buffer (`crdtWriteBehind.service.ts`) to retry next tick. | `test.sh --db` (burst load test) |

## 5. Microsoft-Specific Technical Anchors

### Connection to Azure Cache for Redis & Azure Container Apps
- **Azure Container Apps (ACA) + KEDA:** In enterprise Azure deployments, backend pods run inside ACA and autoscale dynamically based on the queue depth of the Redis write-behind buffer.
- **Enterprise Azure Redis Clustering:** Single Redis instances are replaced by Azure Cache for Redis in a multi-region active-active cluster with automatic DNS failover.

### Distributed Consensus: AP Locks vs. CP Raft (etcd, Azure Cosmos DB)
- Redlock is an **AP distributed lock** (optimistic mutual exclusion with time-to-live expiration).
- Systems like **Azure Cosmos DB** and **Kubernetes (etcd)** use **CP Raft/Paxos consensus** with persistent leader election and deterministic epoch terms.
